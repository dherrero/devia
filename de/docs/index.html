Dokumentation zu Devia Desktop

Was ist Devia Desktop?

Devia Desktop ist eine Desktop-App zur Softwareentwicklung mit KI-Agenten. Sie bietet eine einheitliche Oberfläche für mehrere agentische CLIs (Claude Code, Codex, Gemini CLI und mehr) und verwandelt die Arbeit mit Terminal-Agenten in ein visuelles, strukturiertes und multiprojektfähiges Erlebnis.

Es ist Open Source (Apache-2.0): kostenlos und mit allen Funktionen, verfügbar für Windows, macOS und Linux. Alles läuft lokal, auf deinen Projekten und deinen CLIs; weder ein Konto noch eine Verbindung zu einem Devia-Dienst ist nötig.

Installation

Windows

  1. Lade den Installer .exe von der Download-Seite herunter.
  2. Führe ihn aus und wähle das Installationsverzeichnis (Benutzerinstallation, ohne Administratorrechte).
  3. Wenn SmartScreen eine Warnung anzeigt, klicke auf „Weitere Informationen → Trotzdem ausführen“.

macOS

  1. Lade das .dmg für deine Architektur (Apple Silicon oder Intel) herunter.
  2. Öffne es und ziehe Devia in den Ordner Programme.
  3. Die App ist von Apple signiert und notarisiert: Sie öffnet sich ohne zusätzliche Schritte.

Linux

  1. AppImage: herunterladen, Ausführungsrechte mit chmod +x Devia-*.AppImage setzen und starten.
  2. Debian/Ubuntu: Paket mit sudo dpkg -i devia_*_amd64.deb installieren.

Erste Schritte

  1. Workspace auswählen. Beim ersten Start fragt Devia in einem Dialog nach dem Stammordner deiner Projekte (z. B. ~/repos). Devia listet die enthaltenen Projekte auf und erkennt deren Technologie.
  2. Agenten verbinden. Devia erkennt die auf deiner Maschine installierten agentischen CLIs und lässt dich den aktiven Agenten in den Einstellungen auswählen. Jedes Projekt wird so konfiguriert, dass der Agent ohne manuelle Anpassungen funktioniert.
  3. Loslegen. Öffne ein Projekt und schreibe deine erste Anweisung in das Eingabefeld. Wähle den Ausführungsmodus: plan (nur planen), apply (mit Berechtigungen anwenden) oder apply-yolo (ohne Bestätigungen), je nachdem, wie viel Autonomie du dem Agenten geben möchtest.
  4. Überprüfen. Jede Antwort kommt per Streaming mit markdown, Tool-Aufrufe klappen als Karten auf und die Änderungen des Agenten erscheinen als Inline-Diffs.

Unterstützte Agenten

Devia steuert die folgenden Coding-CLIs, und du kannst zwischen ihnen wechseln, ohne die App zu verlassen. Der Integrationsgrad hängt vom Agenten ab:

AgentIntegration
Claude CodeDie umfassendste: MCP-Server pro Ausführung, Sub-Agent-Karten im Chat und automatisches Fortsetzen nach einem Nutzungslimit.
OpenCodeEigene Integration.
PiEigene Integration.
Kimi und HermesÜber das Agent Client Protocol (ACP). Das Kimi-Profil ist noch nicht gegen das echte CLI verifiziert.
Codex, Gemini CLI, Cursor Agent, GitHub Copilot CLI, Grok, Qwen, Qoder und DeepSeekGenerische Integration über das Streaming des jeweiligen CLIs.
Dein eigener AgentJedes CLI, das ACP spricht, lässt sich in agent-defs.json definieren.

Wenn eine Sitzung mit einem anderen als dem ursprünglichen Agenten fortgesetzt wird, führt Devia einen Kontext-Handoff durch: Es injiziert eine Zusammenfassung der bisherigen Arbeit (Ziel, bearbeitete Dateien und letzte Austausche) in den ersten Zug des neuen Agenten und setzt einen Trenner in den Chat. Die KI-generierte Zusammenfassung erfordert Claude und ANTHROPIC_API_KEY.

Was Devia alles kann

Agenten und Ausführung

  • Die Modi plan, apply und apply-yolo werden pro Sitzung gespeichert. Wie sie angewendet werden, hängt vom Agenten ab: Bei Codex stützt sich der Modus plan zum Beispiel auf die Anweisungen im Prompt.
  • Importiere bestehende Sitzungen von Claude Code, Codex und Grok und setze sie in Devia fort.
  • Mit Claude Code setzt Devia die Sitzung nach einem Nutzungslimit selbst fort, solange die App geöffnet bleibt.
  • Genutzter Kontext, Kosten, Tokens und Kompaktierungen jeder Sitzung, lokal berechnet.
  • Instruktionswarteschlange pro Projekt: Prompts einreihen, während der Agent arbeitet, per Drag-and-drop neu anordnen, pausieren und fortsetzen.
  • Die Aufrufe der Sub-Agenten von Claude Code erscheinen verschachtelt im Chat.

Multiprojekt und geteilte Ansicht

  • Auflisten, Erstellen (leer oder aus Vorlage) und Klonen von Projekten; Favoriten in der Seitenleiste angeheftet.
  • Projekteigener Sitzungsverlauf, der Neustarts übersteht.
  • Bis zu 4 Panels (2×2) im selben Fenster, jedes mit eigener Sitzung und eigenem parallel arbeitenden Agenten.
  • Jedes weitere Panel arbeitet isoliert in seinem eigenen git worktree, damit zwei Agenten nie dieselben Dateien bearbeiten.

Kontext und Gedächtnis

  • Persistentes Gedächtnis über Sitzungen hinweg (devia-memory), persönlich und pro Projekt, mit optionalem semantischem Reranking. Der Agent fragt es ab und befüllt es; du verwaltest es in den Einstellungen.
  • Eigener Code-Graph (6 Sprachen), den die Agenten per MCP abfragen, mit einer Ansicht /graph zum Erkunden.
  • Code mode: Der Agent schreibt ein TypeScript-Skript, das in einer Sandbox über die von dir gewählten MCP-Server läuft und nur das Ergebnis zurückgibt. In dieser Version können die Skripte nur lesen.

Methode und Planung

  • Kanban pro Projekt mit Specs, Aufgaben und Abhängigkeiten, die der Agent per MCP liest und aktualisiert (devia-kanban). Der Zustand liegt außerhalb des Repositorys.
  • Devia Method: eine eigene Entwicklungsmethode (Skills und Start-Prompt), die Devia an alle Agenten ausliefert und die sich pro Projekt aktivieren lässt.
  • Interaktive Karten für jeden Agenten: Fragen, Plan-Freigaben, Änderungs-Reviews, Bestätigungen und Auswahl. Nur auf dem Desktop.
  • Verwaltung von Skills, lokal oder von GitHub, und von wiederverwendbaren Sub-Agenten, die Devia mit jedem CLI synchronisiert.

Git und Review

  • Live-Repository-Status, Inline-Diff-Viewer, Branch-Auswahl und Pull nur als Fast-Forward.
  • Zeilenkommentare im Diff, die dem Agenten als Review-Anfrage gesendet werden.
  • Snapshots mit Wiederherstellung der MCP-, Skills- und Sub-Agenten-Konfiguration, bevor sie geändert wird.
  • Commits, Pushes und Pull Requests erledigt der Agent mit seinen eigenen Werkzeugen: Devia erstellt sie nicht selbst.

MCP-Server

  • Manager für Model-Context-Protocol-Server mit einem Start-Katalog: Server installieren, aktivieren und testen. Devia schreibt die Konfiguration im nativen Format von 9 Agenten.
  • Jeder Server kann dem Agenten direkt oder über code mode angeboten werden.

Fernsteuerung per Telegram

  • Starte Ausführungen, wechsle Modus oder Agent, frage den Status ab (Branch, genutzter Kontext, Kosten) und chatte per Telegram mit dem Agenten.
  • Anhänge an den Agenten senden und vom Agenten erzeugte Dateien empfangen. Optionale Spiegelung des Desktop-Gesprächs.
  • Funktioniert nur, solange Devia geöffnet ist, und bedient einen einzigen autorisierten Chat. Interaktive Karten werden in Telegram nicht angezeigt: Der Agent fragt per Text.

Terminal, Sprache und mehr

  • Integriertes Terminal pro Projekt mit echtem PTY und Öffnen des Projekts in 10 IDEs.
  • Docker-Compose-Orchestrierung: deploy, down und logs pro Projekt.
  • Anhänge beliebigen Typs (bis zu 50 MB pro Datei) und Archiv der vom Agenten erzeugten Dateien.
  • Lokales Diktat per Sprache; derzeit nur auf Spanisch.
  • Audit-Log jedes Tool-Calls.
  • Automatische Aktualisierung der Installationen (unter Linux nur mit AppImage).

Fähigkeiten und Grenzen

Eine ehrliche Zusammenfassung dessen, was Devia heute kann und was noch nicht, damit du weißt, was dich erwartet.

Was es kann

  • 13 agentische CLIs aus einem Fenster steuern, mit den Modi plan, apply und apply-yolo.
  • Geteilte Ansicht mit bis zu 4 Panels und isolierten git worktrees.
  • Kanban, Gedächtnis, Code-Graph und code mode, für den Agenten per MCP zugänglich.
  • Manager für MCP, Skills und Sub-Agenten.
  • Interaktive Karten zum Fragen, Freigeben von Plänen und Prüfen von Änderungen.
  • Zeilenweise Review-Kommentare, die an den Agenten gesendet werden.
  • Fernsteuerung per Telegram, mit Dateiversand.
  • Terminal, Docker Compose und Öffnen in IDEs.

Was es teilweise kann

  • Sitzungen importieren: nur von Claude Code, Codex und Grok.
  • Fortsetzen nach einem Nutzungslimit: nur Claude Code, und nur solange die App geöffnet bleibt.
  • Sub-Agent-Karten im Chat: nur Claude Code.
  • Gedächtnis neu injizieren, wenn der Agent seinen Kontext kompaktiert: nur Claude und Pi.
  • Eigene Agenten: nur solche, die ACP sprechen.
  • Diktat per Sprache: nur auf Spanisch, und die Funktion in der paketierten Version muss noch verifiziert werden.
  • Oberfläche in 11 Sprachen: Spanisch und Englisch sind vollständig; in den übrigen kann es unübersetzte Texte geben.
  • Telegram: nur solange Devia geöffnet ist, mit einem einzigen autorisierten Chat und ohne interaktive Karten.

Was es noch nicht kann

  • Commits erstellen, pushen oder Pull Requests öffnen über die Oberfläche.
  • GitHub, GitLab, Linear oder Jira als Aufgabenquelle nutzen.
  • Integrierter Dateieditor: Der Projektbaum ist schreibgeschützt und Dateien öffnen sich in deiner IDE.
  • Ein Koordinator, der mehrere Worker-Agenten startet und überwacht. Heute ist die Parallelität die geteilte Ansicht, von dir gesteuert.
  • Geplante oder ereignisgesteuerte Automatisierungen.
  • Ausführung auf Remote-Servern per SSH, in der Cloud oder ohne grafische Oberfläche.
  • Eine native Mobile-App: Das Smartphone nutzt du über Telegram.
  • Ein Plugin-System für Panels oder Themes von Drittanbietern.
  • Computersteuerung, mobile Emulatoren oder ein integrierter Browser.

Konfiguration und Daten

Fast alle Daten von Devia liegen auf deiner Festplatte, unter ~/.devia-app/ (unter Windows C:\Users\<dein-benutzer>\.devia-app\):

PfadInhalt
devia-app.config.jsonKonfiguration: Workspace, aktiver Agent, Sprache… (Geheimnisse wie das Telegram-Token werden verschlüsselt gespeichert)
sessions/<projekt>/Chat-Verlauf pro Projekt
projects/<schlüssel>/Daten pro Projekt: Kanban-Board (kanban.json) und Gedächtnis (memory.json)
memory-global.jsonPersönliches Gedächtnis
mcp-servers.jsonKonfigurierte MCP-Server
snapshots/Snapshots der Konfiguration vor ihrer Änderung
worktrees/Git worktrees der zusätzlichen Panels der geteilten Ansicht
attachments/Im Eingabefeld oder per Telegram angehängte Dateien
outbox-archive/Vom Agenten erzeugte Dateien

Um dein Devia zu sichern, genügt es, diesen Ordner zu kopieren. Ihn zu löschen setzt die App in den Ausgangszustand zurück. Das Audit-Log der Tool-Calls wird getrennt im Benutzerdatenordner der Anwendung gespeichert.

Updates

Veröffentlichte Versionen werden im öffentlichen Manifest dieser Website angekündigt: updates/latest.json. Es enthält die neueste verfügbare Version, das Veröffentlichungsdatum, die Hinweise und die Download-Links pro Plattform.

Installationen von Devia Desktop aktualisieren sich selbst aus den Releases des Repositorys (unter Linux nur mit AppImage). Die neueste Version kannst du auch von Hand oder aus deinen Skripten abfragen:

curl -s https://dherrero.github.io/devia/updates/latest.json | jq .version

Häufig gestellte Fragen

Ist Devia kostenlos?

Ja. Devia Desktop ist Open Source (Apache-2.0), mit allen Funktionen, auf allen Plattformen.

Brauche ich ein Konto oder eine Verbindung zu einem Devia-Dienst?

Nein. Devia Desktop läuft lokal. Die einzigen externen Dienste, die genutzt werden, sind die der CLI-Agenten, die du selbst eingerichtet hast.

Enthält Devia die KI-Agenten?

Nein: Devia ist die Oberfläche, die sie steuert. Du musst mindestens ein agentisches CLI (Claude Code, Codex, Gemini CLI, OpenCode…) mit seinen Zugangsdaten installiert haben. Devia erkennt sie und erledigt den Rest.

Verlassen meine Daten meine Maschine?

Sitzungen, Gedächtnis, kanban und Konfiguration liegen in ~/.devia-app/. Auch das Diktat per Sprache läuft lokal. Übertragen wird nur das, was das CLI des von dir genutzten Agenten an seinen eigenen Anbieter sendet.

In welchen Sprachen ist es verfügbar?

Diese Website gibt es auf Spanisch, Englisch, Valencianisch, Französisch, Deutsch, Italienisch, Portugiesisch, Russisch, Chinesisch, Hindi und Arabisch. Die App hat dieselben 11 Sprachen, aber nur Spanisch und Englisch sind vollständig: In den anderen können unübersetzte Texte auftauchen.

Kann ich es vom Smartphone aus steuern?

Ja, über Telegram, solange Devia auf deinem Computer geöffnet ist. Eine native Mobile-App gibt es nicht.

Wie melde ich ein Problem?

Eröffne ein Issue im GitHub-Repository von Devia mit den Schritten zur Reproduktion und deiner Plattform (Windows/macOS/Linux).
