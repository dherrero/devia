توثيق Devia Desktop

ما هو Devia Desktop؟

Devia Desktop تطبيق سطح مكتب لتطوير البرمجيات مع وكلاء الذكاء الاصطناعي. إنه واجهة موحّدة فوق عدة أدوات CLI وكيلة (Claude Code وCodex وGemini CLI والمزيد) تحوّل العمل مع الوكلاء في الطرفية إلى تجربة مرئية ومنظّمة تدعم مشاريع متعددة.

وهو مفتوح المصدر (Apache-2.0): مجاني وبكل الميزات، ومتاح لأنظمة Windows وmacOS وLinux. كل شيء يعمل محليًا، على مشاريعك وأدوات CLI لديك؛ ولا يحتاج إلى حساب ولا إلى اتصال بأي خدمة من Devia.

التثبيت

Windows

  1. نزّل ملف التثبيت .exe من صفحة التنزيلات.
  2. شغّله واختر مجلد التثبيت (تثبيت لكل مستخدم، دون صلاحيات المسؤول).
  3. إذا ظهر تحذير من SmartScreen، فاضغط «مزيد من المعلومات ← تشغيل على أي حال».

macOS

  1. نزّل ملف .dmg المناسب لمعمارية جهازك (Apple Silicon أو Intel).
  2. افتحه واسحب Devia إلى مجلد التطبيقات.
  3. التطبيق موقّع وموثّق (notarized) من Apple: يُفتح دون خطوات إضافية.

Linux

  1. AppImage: نزّله، وامنحه صلاحية التنفيذ بالأمر chmod +x Devia-*.AppImage، ثم شغّله.
  2. Debian/Ubuntu: ثبّت الحزمة بالأمر sudo dpkg -i devia_*_amd64.deb.

الخطوات الأولى

  1. اختر مساحة العمل (workspace). عند فتح Devia للمرة الأولى، تطلب منك نافذة منبثقة المجلد الجذر الذي توجد فيه مشاريعك (مثل ~/repos). يعرض Devia المشاريع الموجودة فيه ويكتشف تقنية كل منها.
  2. اربط وكيلًا. يكتشف Devia أدوات CLI الوكيلة المثبّتة على جهازك ويتيح لك اختيار الوكيل النشط في الإعدادات. يُهيَّأ كل مشروع ليعمل الوكيل دون ضبط يدوي.
  3. ابدأ المحادثة. افتح مشروعًا واكتب أول تعليمة في منطقة الكتابة. اختر وضع التنفيذ: plan (يخطّط فقط)، أو apply (يطبّق بصلاحيات)، أو apply-yolo (دون تأكيدات)، بحسب مقدار الاستقلالية التي تريد منحها.
  4. راجع. يصل كل رد بثًّا مباشرًا مع markdown، وتُعرض استدعاءات الأدوات في بطاقات، وتظهر تغييرات الوكيل كفروق (diffs) مضمّنة.

الوكلاء المدعومون

يوجّه Devia أدوات CLI البرمجية التالية، ويمكنك الانتقال بينها دون مغادرة التطبيق. يختلف مستوى التكامل بحسب الوكيل:

الوكيلالتكامل
Claude Codeالأكمل: خوادم MCP لكل تشغيل، وبطاقات الوكلاء الفرعيين في المحادثة، والاستئناف التلقائي بعد بلوغ حد الاستخدام.
OpenCodeتكامل مخصّص.
Piتكامل مخصّص.
Kimi وHermesعبر Agent Client Protocol (ACP). ملف Kimi لم يُتحقَّق منه بعد مقابل أداة CLI الفعلية.
Codex وGemini CLI وCursor Agent وGitHub Copilot CLI وGrok وQwen وQoder وDeepSeekتكامل عام فوق البثّ المباشر لكل أداة CLI.
وكيلك الخاصيمكن تعريف أي أداة CLI تدعم ACP في agent-defs.json.

عند متابعة جلسة مع وكيل غير الذي بدأها، يجري Devia نقلًا للسياق: يحقن ملخصًا للعمل (الهدف، والملفات التي جرى تعديلها، وآخر التبادلات) في الدور الأول للوكيل الجديد ويترك فاصلًا في المحادثة. الملخص المولَّد بالذكاء الاصطناعي يتطلب Claude وANTHROPIC_API_KEY.

ما الذي يستطيع Devia فعله

الوكلاء والتنفيذ

  • أوضاع plan وapply وapply-yolo تُحفظ لكل جلسة. طريقة تطبيقها تعتمد على الوكيل: ففي Codex مثلًا يستند وضع plan إلى تعليمات الموجِّه (prompt).
  • استورد جلسات موجودة من Claude Code وCodex وGrok وتابعها في Devia.
  • مع Claude Code، يستأنف Devia الجلسة تلقائيًا بعد بلوغ حد الاستخدام، ما دام التطبيق مفتوحًا.
  • السياق المستخدم والتكلفة والرموز (tokens) وعمليات الضغط لكل جلسة، تُحسب محليًا.
  • طابور تعليمات لكل مشروع: ضع prompts في الطابور بينما يعمل الوكيل، وأعد ترتيبها بالسحب والإفلات، وأوقفها مؤقتًا واستأنفها.
  • تظهر استدعاءات الوكلاء الفرعيين في Claude Code متداخلة في المحادثة.

مشاريع متعددة وعرض مقسّم

  • عرض المشاريع وإنشاؤها (فارغة أو من قالب) واستنساخها؛ والمفضلة مثبّتة في الشريط الجانبي.
  • سجل جلسات لكل مشروع يبقى بعد إعادة التشغيل.
  • حتى 4 لوحات (2×2) في النافذة نفسها، لكلٍّ منها جلستها ووكيلها يعملان بالتوازي.
  • تعمل كل لوحة إضافية معزولة في git worktree خاص بها، حتى لا يكتب وكيلان فوق الملفات نفسها أبدًا.

السياق والذاكرة

  • ذاكرة دائمة بين الجلسات (devia-memory)، شخصية ولكل مشروع، مع إعادة ترتيب دلالية اختيارية. يستشيرها الوكيل ويغذّيها، وتديرها أنت في الإعدادات.
  • رسم بياني للشيفرة (6 لغات) يستعلم عنه الوكلاء عبر MCP، مع واجهة /graph لاستكشافه.
  • Code mode: يكتب الوكيل سكربت TypeScript يُنفَّذ في بيئة معزولة (sandbox) على خوادم MCP التي تختارها، ولا يعيد إلا النتيجة. في هذا الإصدار تقتصر السكربتات على القراءة.

المنهجية والتخطيط

  • لوحة kanban لكل مشروع مع مواصفات ومهام وتبعيات، يقرؤها الوكيل ويحدّثها عبر MCP (devia-kanban). تُحفظ الحالة خارج المستودع.
  • Devia Method: منهجية تطوير خاصة (skills وprompt بدء) يسلّمها Devia لجميع الوكلاء، ويمكن تفعيلها لكل مشروع.
  • بطاقات تفاعلية لأي وكيل: أسئلة، وموافقة على الخطط، ومراجعة التغييرات، وتأكيدات، واختيارات. على سطح المكتب فقط.
  • مدير skills، محلية أو من GitHub، ومدير للوكلاء الفرعيين القابلين لإعادة الاستخدام، يزامنهما Devia مع كل أداة CLI.

Git والمراجعة

  • حالة المستودع مباشرة، وعارض فروق مضمّنة، ومحدّد فروع، وpull بنمط fast-forward فقط.
  • تعليقات على أسطر الفروق تُرسل إلى الوكيل كطلب مراجعة.
  • لقطات (snapshots) مع استعادة لإعدادات MCP وskills والوكلاء الفرعيين قبل تعديلها.
  • الـ commits والـ push وطلبات الدمج (pull requests) ينفّذها الوكيل بأدواته الخاصة: Devia لا ينشئها بنفسه.

خوادم MCP

  • مدير لخوادم Model Context Protocol مع كتالوج أولي: ثبّت الخوادم وفعّلها واختبرها. يكتب Devia الإعداد بالصيغة الأصلية لـ 9 وكلاء.
  • يمكن إتاحة كل خادم للوكيل مباشرة أو عبر code mode.

التحكم عن بُعد عبر Telegram

  • شغّل عمليات التنفيذ، وبدّل الوضع أو الوكيل، واطلع على الحالة (الفرع، والسياق المستخدم، والتكلفة)، وتحدّث مع الوكيل من Telegram.
  • إرسال مرفقات إلى الوكيل واستلام الملفات التي يولّدها. مرآة اختيارية لمحادثة سطح المكتب.
  • يعمل فقط ما دام Devia مفتوحًا، ويخدم محادثة واحدة مصرّحًا بها. لا تظهر البطاقات التفاعلية في Telegram: يسأل الوكيل بنص.

الطرفية والصوت والمزيد

  • طرفية مدمجة لكل مشروع بـ PTY حقيقية، وفتح المشروع في 10 بيئات تطوير (IDE).
  • إدارة Docker Compose: deploy وdown وlogs لكل مشروع.
  • مرفقات من أي نوع (حتى 50 MB للملف الواحد) وأرشفة الملفات التي يولّدها الوكيل.
  • إملاء صوتي محلي؛ حاليًا بالإسبانية فقط.
  • سجل تدقيق لكل tool-call.
  • تحديث تلقائي لعمليات التثبيت (على Linux، مع AppImage فقط).

الإمكانات والحدود

ملخص صريح لما يفعله Devia اليوم ولما لا يفعله بعد، لتعرف ما يمكنك توقعه.

ما يفعله

  • إدارة 13 أداة CLI وكيلة من نافذة واحدة، بأوضاع plan وapply وapply-yolo.
  • عرض مقسّم حتى 4 لوحات مع git worktrees معزولة.
  • kanban والذاكرة والرسم البياني للشيفرة وcode mode متاحة للوكيل عبر MCP.
  • مدير لـ MCP وskills والوكلاء الفرعيين.
  • بطاقات تفاعلية للسؤال والموافقة على الخطط ومراجعة التغييرات.
  • تعليقات مراجعة على الأسطر تُرسل إلى الوكيل.
  • تحكم عن بُعد عبر Telegram مع إرسال الملفات.
  • الطرفية وDocker Compose وفتح المشروع في بيئات التطوير.

ما يفعله جزئيًا

  • استيراد الجلسات: من Claude Code وCodex وGrok فقط.
  • الاستئناف بعد بلوغ حد الاستخدام: Claude Code فقط، وما دام التطبيق مفتوحًا فقط.
  • بطاقات الوكلاء الفرعيين في المحادثة: Claude Code فقط.
  • إعادة حقن الذاكرة عندما يضغط الوكيل سياقه: Claude وPi فقط.
  • الوكلاء الخاصون: الذين يدعمون ACP فقط.
  • الإملاء الصوتي: بالإسبانية فقط، وعمله في النسخة المُحزَّمة لم يُتحقَّق منه بعد.
  • واجهة بـ 11 لغة: الإسبانية والإنجليزية مكتملتان؛ وفي البقية قد توجد نصوص غير مترجمة.
  • Telegram: ما دام Devia مفتوحًا فقط، مع محادثة واحدة مصرّح بها، ودون بطاقات تفاعلية.

ما لا يفعله بعد

  • إنشاء commits أو تنفيذ push أو فتح pull requests من الواجهة.
  • استخدام GitHub أو GitLab أو Linear أو Jira كمصدر للمهام.
  • محرر ملفات مدمج: شجرة المشروع للقراءة فقط، وتُفتح الملفات في بيئة التطوير لديك.
  • منسّق يطلق عدة وكلاء عاملين ويشرف عليهم. اليوم التوازي هو العرض المقسّم الذي توجّهه أنت.
  • أتمتة مجدولة أو مُطلَقة بالأحداث.
  • التشغيل على خوادم بعيدة عبر SSH، أو في السحابة، أو دون واجهة رسومية.
  • تطبيق جوال أصلي: يُستخدم الجوال عبر Telegram.
  • نظام إضافات (plugins) للوحات أو سمات من جهات خارجية.
  • التحكم بالحاسوب، أو محاكيات الجوال، أو متصفح مدمج.

الإعدادات والبيانات

تقريبًا كل معلومات Devia محفوظة على قرصك، تحت ~/.devia-app/ (وعلى Windows، C:\Users\<tu-usuario>\.devia-app\):

المسارالمحتوى
devia-app.config.jsonالإعدادات: workspace، والوكيل النشط، واللغة، وغيرها (الأسرار، مثل رمز Telegram، تُحفظ مشفّرة)
sessions/<proyecto>/سجل المحادثات لكل مشروع
projects/<clave>/بيانات كل مشروع: لوحة Kanban (kanban.json) والذاكرة (memory.json)
memory-global.jsonالذاكرة الشخصية
mcp-servers.jsonخوادم MCP المُعدّة
snapshots/لقطات من الإعدادات قبل تعديلها
worktrees/Git worktrees للوحات الإضافية في العرض المقسّم
attachments/الملفات المرفقة في منطقة الكتابة أو عبر Telegram
outbox-archive/الملفات التي ولّدها الوكيل

لأخذ نسخة احتياطية من Devia يكفي نسخ ذلك المجلد. وحذفه يعيد التطبيق إلى حالته الأولى. أما سجل تدقيق الـ tool-calls فيُحفظ منفصلًا، في مجلد بيانات المستخدم الخاص بالتطبيق.

التحديثات

تُعلَن الإصدارات المنشورة في البيان العام لهذا الموقع: updates/latest.json. يتضمن أحدث إصدار متاح، وتاريخ النشر، والملاحظات، وروابط التنزيل لكل منصة.

تُحدّث عمليات تثبيت Devia Desktop نفسها تلقائيًا من Releases المستودع (على Linux، مع AppImage فقط). ويمكنك أيضًا الاطلاع على أحدث إصدار يدويًا أو من سكربتاتك:

curl -s https://dherrero.github.io/devia/updates/latest.json | jq .version

الأسئلة الشائعة والإجابات

هل Devia مجاني؟

نعم. Devia Desktop مفتوح المصدر (Apache-2.0)، بكل الميزات، على جميع المنصات.

هل أحتاج إلى حساب أو اتصال بأي خدمة من Devia؟

لا. يعمل Devia Desktop محليًا. الخدمات الخارجية الوحيدة المستخدمة هي خدمات أدوات CLI الوكيلة التي أعددتها أنت.

هل يتضمن Devia وكلاء الذكاء الاصطناعي؟

لا: Devia هو الواجهة التي توجّههم. تحتاج إلى تثبيت أداة CLI وكيلة واحدة على الأقل (Claude Code أو Codex أو Gemini CLI أو OpenCode…) مع بيانات اعتمادها. يكتشفها Devia ويتولى الباقي.

هل تغادر بياناتي جهازي؟

الجلسات والذاكرة وkanban والإعدادات محفوظة في ~/.devia-app/. والإملاء الصوتي يعمل محليًا أيضًا. الشيء الوحيد الذي ينتقل هو ما ترسله أداة CLI الخاصة بالوكيل الذي تستخدمه إلى مزوّدها.

بأي لغات يتوفر؟

هذا الموقع متاح بالإسبانية والإنجليزية والفالنسية والفرنسية والألمانية والإيطالية والبرتغالية والروسية والصينية والهندية والعربية. وللتطبيق اللغات الإحدى عشرة نفسها، لكن الإسبانية والإنجليزية فقط مكتملتان: في البقية قد تظهر نصوص غير مترجمة.

هل يمكنني التحكم به من الجوال؟

نعم، عبر Telegram، شريطة أن يكون Devia مفتوحًا على حاسوبك. لا يوجد تطبيق جوال أصلي.

كيف أبلغ عن مشكلة؟

افتح بلاغًا في مستودع Devia على GitHub مع خطوات إعادة إنتاجها ومنصتك (Windows/macOS/Linux).
